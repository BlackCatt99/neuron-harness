# 相关性筛选模板（注入主模型，档 2 邻域召回用；档 1 跳过本模板）

## 依赖图导航
1. 读工作集「依赖图」节，找本次指令直接触碰的节点
2. 沿边扩散：直接节点 + 一跳邻居（用户明说影响面大才两跳）
3. 注意时序：检索依赖**归档阶段更新后的**依赖图——新消息引入新模块时，先完成归档
   （含依赖图更新）再检索；信号只负责升档，不负责建图
4. 层过滤固定 `-Tier t2,t3`（decisions 决策在 T3 层）

## 输出契约（钉死，harness 依此逐项执行 Search）
```json
{"nodes": ["节点名"], "tags": ["标签"], "query": "补充查询串"}
```
- **nodes 必须逐字取自工作集依赖图**，不得自造节点名——图上没有的节点写进 nodes
  等于白写，Search 匹配不到
- **tags 必须取自 config 词表或既有条目标签**；确需词表外新词，在输出后单列
  `NEW-TAG: <词>` 交 harness 确认入表后再用
- **query 仅作兜底**：nodes/tags 检索均为空时才用；命中非空不得追加自由文本查询
- harness 执行：nodes 逐个 `Search -TaskId <id> -Query <节点> -Tier t2,t3`；
  tags 跑 `-Tags`；均空才跑 query

## 证据取舍
- 直接因果/约束相关 → 入 Evidence 列表（冷存条目照带：渲染靠后、裁剪受脚本保护）
- 仅背景相关 → 不带
- 漏带硬约束级证据的代价 > 多带三条背景证据：拿不准的强相关带上，弱相关不带
- 考古（更早被遗忘的旧决策）：`Search -Tier t4` 查到后 Fetch 原文，id 可直接入包
  （层只管检索可见性，入包白名单只看类型）——TierSweep 会按 access 自动重算层位

输出：`Evidence: <id1,id2,...>；理由: <一句话>`
